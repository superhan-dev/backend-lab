# v1.0.0 랭킹 시스템 구축 초안

## 1) 목표와 범위
- Redis Sorted Set 기반 실시간 랭킹 제공.
- RDB(`rankings`)는 원천 데이터 저장소로 사용하고, 필요 시 재계산/스냅샷 가능하도록 설계.
- 점수 정책 두 가지를 모두 지원: 최고 점수(최대값) / 누적 점수(합산).
- 구현 방향: 클린 아키텍처 기반으로 도메인/유스케이스/인터페이스/인프라 계층 분리(도메인 로직은 Redis/DB/Kafka 세부 구현과 분리).

## 2) 데이터 모델 (RDB)
- `rankings` 테이블 (플레이 로그/원천 데이터)
  - `id` (PK, auto increment)
  - `user_id` (FK to users)
  - `score` (해당 플레이 점수)
  - `play_at` (플레이 종료/확정 시각, DATETIME)
  - 선택: `mode`, `stage`, `season_id`
- 인덱스 권장
  - `idx_rankings_user_id`
  - `idx_rankings_play_at`
  - 모드/시즌 분리 시 `(season_id, score DESC)` 또는 `(mode, play_at)`
- 진실성 원칙
  - RDB = 단일 진실 소스. Redis는 뷰이므로 깨져도 RDB 기준 재생성 가능.

## 3) Redis 실시간 랭킹 설계
- 키 네이밍
  - 글로벌: `ranking:global`
  - 일간: `ranking:daily:YYYY-MM-DD`
  - 모드/시즌: `ranking:mode:<mode>:<YYYY-MM-DD>` 또는 `ranking:season:<seasonId>`
- 멤버/스코어
  - 멤버: `user_id` (정수/문자열)
  - 스코어: 정책별로 결정
    - 최고 점수: 사용자 최고 점수
    - 누적 점수: 사용자 누적 점수
- 업데이트 패턴
  - 최고 점수: `ZADD <key> GT <score> <userId>`
  - 누적 점수: `ZINCRBY <key> <deltaScore> <userId>`
- 조회 패턴
  - Top N: `ZREVRANGE <key> 0 N-1 WITHSCORES`
  - 내 순위/점수: `ZREVRANK <key> <userId>`, `ZSCORE <key> <userId>`
  - 주변 랭킹: 내 rank 기준 offset 계산 후 `ZREVRANGE`
- 키 수명
  - 시즌/일간 키는 필요 시 TTL 또는 백업 후 삭제. 기본은 유지(백필 대비).

## 4) 쓰기 플로우 (점수 기록)
1) 입력 수신: `(user_id, score, play_at, mode/season_id...)`
2) RDB `rankings` Insert (트랜잭션 내부에서 유효성 검사 포함).
3) Redis 업데이트
   - 최고 점수 정책: `ZADD ... GT`
   - 누적 점수 정책: `ZINCRBY ...`
4) 실패 처리
   - RDB 실패: 전체 롤백, 클라이언트에 에러 반환.
   - Redis 실패: RDB는 남기고 경고 로그/알림. 백필 잡으로 재구축.

## 5) 읽기 플로우 / API 스케치
- Top N: `GET /rankings/top?type=global&limit=100&mode=...&date=...`
  - 키 결정 → Redis Top N → user profile 조회 조인.
- 내 순위: `GET /rankings/me?type=...`
  - 키 결정 → `ZREVRANK` + `ZSCORE`.
- 내 주변: `GET /rankings/around-me?type=...&range=2`
  - 키 결정 → 내 rank → 위/아래 range 계산 후 `ZREVRANGE`.
- 폴백
  - 키 없음/손상 시: 관리용 리빌드 잡 트리거 또는 임시 RDB ORDER BY 응답(성능 비용 감수).

## 6) 운영/배치
- 리빌드/백필 잡
  - 입력: 기간/모드/시즌.
  - RDB 집계 → Redis 키 재구성(`ZADD` bulk) → 필요 시 스냅샷 테이블 기록.
- 스냅샷 잡(옵션)
  - 예: 일간/시즌 마감 시 Top N을 `ranking_snapshot`에 저장.
  - 이후 보상/리포트는 스냅샷 기준 사용.
- 모니터링
  - Redis 명령 실패율, 키 존재 여부, 랭킹 재빌드 소요 시간, API 레이턴시/에러율 알림.

## 8) 성능 관측/로그 분석 구축 (p95/p90 측정)

  - [ ] 샘플링 정책: 정상 1~5%, 오류 100%, 피크 시 동적 샘플링.

  - [ ] 슬로우 로그 룰: p95 초과/타임아웃 발생 시 경고 이벤트 생성.

## 9) 클린 아키텍처 구현 스켈레톤
- 도메인: `ranking.domain` (엔티티/값객체/정책), `ranking.domain.port` (RecordRepository, LeaderboardPort).
- 유스케이스: `ranking.application` (SubmitScore, RankingQuery, RankingKeyFactory).
- 인터페이스/프레젠테이션: `ranking.presentation` (REST DTO/Controller).
- 인프라: `ranking.infrastructure.persistence` (JPA entity/repo), `ranking.infrastructure.redis` (Sorted Set 어댑터).
- 의존성 흐름: 프레젠테이션/인프라 → 유스케이스 → 도메인; 도메인은 외부 프레임워크에 무관.
